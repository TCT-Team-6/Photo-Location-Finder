Whereabouts AI Guide — implementation and verification

Approved scope
Live cases organize user-reported facts and reference evidence, with no photo
analysis, face matching or inferred whereabouts. Every call, copy, download,
share and print action requires a user tap. Existing upload/analysis screens,
urgency.ts and the five-stage analysis pipeline were not modified.

Implemented
- Home and Start a search entry: typed input, optional voice input with typed
  fallback, photo attachment, three examples and the regular-form link.
- Private authenticated intake using GPT-4o strict structured output.
- Missing-fact followups bounded to three, emergency instruction and Call 911.
- Persisted safety decisions, case transcript, reported facts and optional notes.
- Regular case fields synchronized with guide facts; revision conflict protection.
- Reference photos use the existing private case-evidence upload flow.
- Responder summaries use canonical reported data, not speculative AI prose.
  Live summaries do not assign invented confidence values.
- Alex and Grandpa Joe demos use saved replies/results and a fixed scoring clock.
  Every demo screen and printable output says "Sample case, fictional data".
- Grounded cards, Why this disclosures, map links, checked-place reordering,
  summary sharing/printing, and a fictional sample flyer.
- Demo 911 buttons simulate a call; only live-case buttons use tel:911.

Verification
- All runnable unit/API test scripts: 138 passed (69 frontend, 69 API).
- Browser regression suite: 5 passed, including both guided demos, offline/no
  write behavior, grounding, checked-place reordering and phone-width layout.
- Workspace-wide typecheck: passed.
- Preview screenshot: guided Grandpa Joe page rendered on a phone viewport.
- Signed-in browser test: created a private case with consent and verified
  failure handling and deletion. The live extraction was blocked by provider
  quota before followups, correction synchronization or summary could be tested.
- Direct provider diagnostic returned HTTP 429, credit_balance_exhausted,
  insufficient_quota. The app now displays a specific no-credits explanation.
  No replacement provider, secrets or account settings were changed.
- Ownership, gate persistence, concurrent-edit protection, note persistence,
  summary grounding and quota failure are covered by API/unit tests.

PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/repl/tools/bin/chromium pnpm --filter @workspace/whereabouts run test:e2e

The initial local browser run lacked Playwright's downloaded browser. Tests now
support an optional executable-path environment variable and were run with the
installed Chromium. The existing demo browser test excludes the preview-only
platform banner, which otherwise covered its dialog close control.

Remaining external blocker
Restore credits for the configured AI provider before verifying live intake,
followups, corrections and responder-summary creation end to end. Demos require
no provider calls. Nothing was published.
